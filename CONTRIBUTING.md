# Руководство по внесению вклада

Спасибо за интерес к улучшению FunPay Customizer! Мы рады любым предложениям и улучшениям.

## 🚀 Быстрый старт

1. **Форкните репозиторий**
2. **Клонируйте ваш форк**:
   ```bash
   git clone https://github.com/ваш-username/funpay-customizer.git
   cd funpay-customizer
   ```
3. **Создайте ветку для вашей функции**:
   ```bash
   git checkout -b feature/amazing-feature
   ```

## 📝 Стандарты кода

### JavaScript
- Используйте ES6+ синтаксис
- Именование переменных: camelCase
- Именование констант: UPPER_SNAKE_CASE
- Используйте `const` и `let`, избегайте `var`
- Добавляйте комментарии для сложной логики
- Следите за читаемостью кода

### CSS
- Используйте BEM методологию для именования классов (где применимо)
- Группируйте похожие стили вместе
- Используйте CSS переменные для цветов и повторяющихся значений
- Добавляйте комментарии для сложных стилей

### HTML
- Используйте семантические теги
- Добавляйте атрибуты `aria-*` для доступности
- Поддерживайте правильную вложенность

## 🎯 Типы изменений

### Новые функции
- Добавьте описание функции в README.md
- Обновите интерфейс при необходимости
- Убедитесь, что функция работает во всех поддерживаемых браузерах

### Исправление багов
- Опишите проблему в коммите
- Добавьте информацию о том, как баг был воспроизведен
- Объясните, как исправление решает проблему

### Улучшение UI/UX
- Приложите скриншоты до и после
- Объясните, почему изменение улучшает пользовательский опыт
- Убедитесь, что дизайн согласуется с общим стилем расширения

### Оптимизация
- Опишите, что было оптимизировано
- Предоставьте данные о производительности (если применимо)
- Убедитесь, что оптимизация не ломает существующую функциональность

## 🧪 Тестирование

Перед отправкой Pull Request:

1. **Проверьте работу в разных браузерах**:
   - Chrome
   - Firefox
   - Edge

2. **Проверьте основные функции**:
   - Смена тем
   - Применение шрифтов
   - Загрузка обложек
   - Сохранение настроек

3. **Проверьте на разных разрешениях экрана**

4. **Убедитесь, что нет консольных ошибок**

## 📬 Отправка Pull Request

1. **Закоммитьте изменения**:
   ```bash
   git add .
   git commit -m "Add: описание вашего изменения"
   ```

2. **Запушьте в ваш форк**:
   ```bash
   git push origin feature/amazing-feature
   ```

3. **Создайте Pull Request**:
   - Перейдите на GitHub
   - Нажмите "New Pull Request"
   - Заполните шаблон описания
   - Добавьте скриншоты при необходимости

### Формат сообщения коммита

Используйте следующий формат:
```
Тип: Краткое описание (макс 50 символов)

Подробное описание изменений (если необходимо)

- Пункт 1
- Пункт 2
```

Типы коммитов:
- `Add`: Добавление новой функции
- `Fix`: Исправление бага
- `Update`: Обновление существующей функции
- `Refactor`: Рефакторинг кода
- `Style`: Изменения в стилях
- `Docs`: Изменения в документации
- `Perf`: Улучшение производительности

## 🐛 Сообщение о багах

При обнаружении бага создайте Issue с:

1. **Описанием проблемы**
2. **Шагами для воспроизведения**
3. **Ожидаемым поведением**
4. **Фактическим поведением**
5. **Скриншотами** (если применимо)
6. **Информацией о браузере и версии**

## 💡 Предложение новых функций

Создайте Issue с:

1. **Описанием функции**
2. **Причиной, почему она нужна**
3. **Примерами использования**
4. **Возможным вариантом реализации** (опционально)
5. **Макетами/скриншотами** (если применимо)

## ⚠️ Важные замечания

- **Не ломайте существующую функциональность**
- **Следуйте существующему стилю кода**
- **Тестируйте перед отправкой**
- **Будьте вежливы и конструктивны**
- **Обновляйте документацию при необходимости**
